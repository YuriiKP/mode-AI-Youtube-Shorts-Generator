# AI YouTube Shorts Generator

Превращает одно длинное видео (ссылка YouTube, локальный файл или папка) в
ранжированные вертикальные шортсы **9:16** — полностью локально, без водяных
знаков и без лимитов на минуты. `yt-dlp` скачивает исходник, `faster-whisper`
распознаёт речь, LLM (OpenAI / DeepSeek / Gemini) ранжирует самые «вирусные»
моменты, а `ffmpeg` + OpenCV кадрируют их вертикально. Опционально можно добавить
**фоновую музыку**, **вшить субтитры**, довести кадр до **9:16** с размытым фоном
и наложить **баннер** (картинку или текстовую полосу).

> Бесплатная альтернатива Opus Clip / Vidyo.ai / Klap.

## Установка

```bash
git clone https://github.com/SamurAIGPT/AI-Youtube-Shorts-Generator.git
cd AI-Youtube-Shorts-Generator
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env              # Windows: copy .env.example .env
```

Требования: Python 3.10+, `ffmpeg` в `PATH` и один ключ LLM.

## Настройка

Всё живёт в одном файле `.env` (скопируйте из `.env.example`). Самое главное:

```env
INPUT=video/talk.mkv      # файл, папка с видео или ссылка на YouTube
OUTPUT_DIR=output         # куда писать результат
MUSIC=music               # файл с музыкой или папка (необязательно)
```

Провайдер выбирается через `LLM_PROVIDER`, его ключ — `OPENAI_API_KEY`,
`DEEPSEEK_API_KEY` или `GEMINI_API_KEY`. Остальные ключи (Whisper, вид субтитров,
кодирование) описаны в `.env.example`. Любой флаг команды перекрывает `.env` на
один запуск.

Опциональная индексация визуала включается через `VISUAL_INDEXER_ENABLED=true` и
движок `VISUAL_INDEXER_TYPE` (`florence` — локально, `gemini` — облако по
кадрам, `gemini_video` — облако целиком, `none` — выключено). Остальные
ключи — `VISUAL_INDEXER_*` в `.env.example`.

Результат индексации визуала кэшируется в `OUTPUT_DIR` (`<video>.visual.json`,
например `video/talk.mkv` → `output/talk.visual.json`) — так же, как транскрипт
в `.srt`, — и переиспользуется на следующих запусках. Поэтому повторная нарезка
того же ролика — с другим `NUM_CLIPS`, аспектом или любыми другими настройками
клипов — не гоняет запросы к Gemini/Florence заново: описания берутся из кэша,
пока само видео и параметры индексатора (движок, модель, пороги сцен) не
изменились. Кэш включается флагом `VISUAL_INDEXER_CACHE=true` (по умолчанию
включён) и сбрасывается выключением (`VISUAL_INDEXER_CACHE=false`) либо
удалением файла — тогда индекс строится заново.

## Команды

```bash
python main.py clip         # нарезать исходник в ранжированные вертикальные шортсы
python main.py transcribe   # Whisper -> <видео>.srt (файл или папка)
python main.py music        # добавить музыку (MUSIC: файл или папка)
python main.py subtitles    # вшить субтитры (из .srt или через Whisper)
python main.py preview      # один случайный кадр — быстро увидеть итог настроек картинки
python main.py all          # нарезка + музыка + субтитры одной командой
```

Каждая команда читает `INPUT` / `OUTPUT_DIR` из `.env` и принимает:

| Флаг | Значение |
|---|---|
| `-i, --input` | видео, папка или ссылка (по умолчанию `INPUT`) |
| `-o, --output-dir` | куда писать результат (по умолчанию `OUTPUT_DIR`) |
| `-q, --quiet` | только предупреждения и ошибки |
| `--no-timing` | не печатать в конце сводку затраченного времени |
| `--env FILE` | дополнительный `.env` (наивысший приоритет) |

### Примеры

```bash
python main.py clip -i "video/talk.mkv" -n 5 -a 9:16 -l ru
python main.py transcribe -i video/            # все видео в папке
python main.py music -m music/                 # случайный трек из папки
python main.py music -m song.mp3               # конкретный файл
python main.py subtitles                       # одноимённый .srt, иначе Whisper
python main.py subtitles --banner "@mychannel"   # вшить субтитры + текстовый баннер
python main.py subtitles --banner assets/logo.png --banner-position top  # баннер-картинка
python main.py all --banner "@mychannel" --banner-position bottom   # весь пайплайн + баннер
python main.py all                             # весь пайплайн из .env
python main.py clip --slide                     # нарезка со скольжением по кадру
python main.py preview                          # тестовый кадр для подбора картинки
python main.py preview --saturation 1.2 --background-blur 40   # тест эффектов без рендера
```

- **clip**: `-n/--num-clips`, `-a/--aspect-ratio`, `--format`, `-l/--language`,
  `--[no-]face-tracking`, `--[no-]slide`, `--slide-transition-gap`,
  `--slide-range`, `--output-json`.
- **subtitles** (`-s/--source`, по умолчанию `auto`): если рядом с видео лежит
  одноимённый `.srt` — берётся он, иначе сначала идёт распознавание. `file` —
  только готовый файл (иначе ошибка), `whisper` — всегда распознавать, `none` —
  не трогать субтитры.
- **music**: если `MUSIC` — папка, берётся случайный трек, если файл — именно он.
  Музыка подмешивается *под* голос, поэтому дорожка речи не теряется. Команда
  работает **только со звуком**: картинка не трогается — ни цветокоррекция,
  ни `SPEED`, ни вертикальный кадр, ни баннер к ней не применяются.
- **вертикальный кадр и баннер** (`subtitles` и `all`):
  `--[no-]fit-vertical`, `--fit-aspect-ratio W:H`, `--background-blur N`,
  `--banner TEXT|PATH`, `--banner-position {top,bottom,center}`.
- **preview**: `--[no-]subtitles-enabled`, `--count N`, `--time SECONDS` плюс все
  флаги картинки из «вертикальный кадр и баннер». Рендерит один случайный кадр и
  сохраняет его в `OUTPUT_DIR/preview_frame.png`.

## Субтитры

Субтитры вшиваются короткими репликами: длинное предложение Whisper нарезается
на отдельные фразы, поэтому на экране всегда висит одна короткая фраза, а не
«простыня» на пол-экрана на десять секунд.

- Реплики строятся по таймингам **отдельных слов** (`word_timestamps`), поэтому
  текст появляется и исчезает синхронно с голосом. Новая реплика начинается на
  конце предложения, на заметной паузе в речи или после запятой/тире, если фраза
  уже достаточно длинная.
- Длину реплики ограничивают три настройки в `.env`:
  - `SUBTITLE_MAX_CHARS` — максимум символов в реплике (по умолчанию `40`);
  - `SUBTITLE_MAX_WORDS` — максимум слов (по умолчанию `9`);
  - `SUBTITLE_MAX_DURATION` — максимум секунд на экране (по умолчанию `3.5`).
- **Пауза между репликами** — `SUBTITLE_PAUSE_THRESHOLD` (в секундах, по умолчанию
  `0.6`). Когда в речи между двумя словами возникает тишина не короче этого
  значения, текущая реплика закрывается, а следующее слово начинает новую. Так
  субтитр завершается на естественной паузе, а во время тишины текст пропадает
  с экрана. Меньше значение — реплики короче и их больше (тишина гасит текст
  чаще); больше — реплики длиннее и текст висит на экране сквозь короткие паузы.
  Действует только при наличии таймингов по словам (`word_timestamps`); для
  готового `.srt` без слов время распределяется по длине фраз и порог не
  применяется.
- Тот же разрез применяется и к готовому `.srt` (старый кэш или свой файл):
  перед вшиванием длинные строки дробятся на короткие фразы.
- **Синхронность с речью** — `SUBTITLE_OFFSET` (в секундах, по умолчанию `0.0`).
  Тайминги отдельных слов Whisper иногда «забегают» вперёд реальной речи, из-за
  чего реплика появляется на долю секунды раньше фразы. Положительное значение
  сдвигает показ **позже** (например `SUBTITLE_OFFSET=0.2`), отрицательное —
  раньше. Сдвигается только показ субтитров на видео; сам кэш `.srt` сохраняет
  исходные тайминги.
- **Анимация появления** реплики — `SUBTITLE_ANIMATION` (пусто = без анимации,
  по умолчанию). Доступные значения:
  - `fade` — реплика просто проявляется;
  - `slide` — проявляется, всплывая снизу вверх;
  - `pop` — проявляется, увеличиваясь с 70% до 100%.
  Длительность входа задаёт `SUBTITLE_ANIMATION_DURATION` (в секундах, по
  умолчанию `0.25`). Анимация проигрывается только в начале реплики, дальше
  текст стоит на месте. Пустое значение `SUBTITLE_ANIMATION` (а также
  `none`/`off`) отключает анимацию полностью.
- Кэш `.srt` создаётся уже нарезанным на реплики. Если рядом с видео лежит
  **старый** `.srt` (одна строка = одно длинное предложение), удалите его один
  раз — при следующем запуске `transcribe` / `subtitles` / `all` текст
  распознается заново уже с таймингами по словам.

## Вертикальный кадр, баннер и эффекты

Эти возможности применяются в постобработке — в том же шаге, где вшиваются
субтитры (команды `subtitles` и `all`). Команда `music` их **не** применяет:
она подмешивает только звук и оставляет картинку без изменений.

- **Вертикальный кадр** (`FIT_VERTICAL=true`, включён по умолчанию). Если видео
  после нарезки не совпадает по пропорциям с `FIT_ASPECT_RATIO` (по умолчанию
  `9:16`), оно вписывается по центру, а пустые места закрывает размытая копия
  этого же видео. Уже вертикальные видео не пересобираются. Настройки:
  `FIT_ASPECT_RATIO` (пусто = взять `ASPECT_RATIO`), `FIT_HEIGHT` (высота кадра,
  по умолчанию 1920), `BACKGROUND_BLUR` (сила размытия, 0 = без размытия),
  `BACKGROUND_DARKEN` (затемнение фона, 0..1).
- **Баннер** (`BANNER`). Один аргумент: если значение указывает на существующий
  файл — рисуется картинкой (`PNG` с прозрачностью или `JPG`), иначе само значение
  рисуется текстовой полосой во всю ширину кадра. Настройки: `BANNER_POSITION`
  (`top`/`bottom`/`center`), `BANNER_WIDTH_RATIO`, `BANNER_OPACITY`,
  `BANNER_MARGIN`, `BANNER_FONT_SIZE`, `BANNER_TEXT_COLOR`,
  `BANNER_BACKGROUND_COLOR`.
- **Цветокоррекция и эффекты**. Настройки: `SATURATION` (множитель насыщенности:
  `1.0` — как в исходнике, `0` — ч/б, значения выше `1` делают цвет ярче; по
  умолчанию `1.0`), `SHARPNESS` (сила нерезкого маскирования: `0` отключает,
  `1.0` — мягко, `2.0` — сильно; по умолчанию `0`), `CHROMATIC_ABERRATION`
  (сдвиг красного и синего каналов в противоположные стороны на N пикселей —
  цветная «каёмка» на контурах; `0` отключает) и `SPEED` (скорость
  воспроизведения: `1` — обычная, `1.5` — на 50% быстрее, `0.5` — вдвое
  медленнее; ускоряется и видео, и звук, поэтому звук не «отстаёт», а субтитры
  остаются синхронными). Все параметры насыщенности/резкости/аберрации по
  умолчанию нейтральны и не меняют картинку, а `SPEED` по умолчанию равен `1`.
- Эти эффекты выполняет сам **FFmpeg** отдельным быстрым проходом по исходному
  видео (фильтры `eq` / `unsharp` / `rgbashift`, многопоточно, без покадровой
  обработки в Python), поэтому рендер не замедляется. Накладываются они только на
  видео — субтитры и баннер рисуются поверх уже подготовленного кадра и остаются
  чёткими. С этим же проходом работают и приёмы уникализации из раздела
  «Уникализация» ниже (дополнительные фильтры `hflip` / `crop`+`scale` / `noise` /
  `hue`): они применяются к тому же подготовленному кадру до наложения субтитров и
  баннера.

Примеры:

```bash
# текстовый баннер во всю ширину кадра (полоса с текстом сверху)
python main.py subtitles -i "video/talk.mkv" --banner "@mychannel"

# баннер-картинка (PNG с прозрачностью) внизу кадра
python main.py subtitles -i "video/talk.mkv" --banner "assets/logo.png" --banner-position bottom

# баннер в полном пайплайне: нарезка + музыка + субтитры + баннер 9:16
python main.py all --banner "@mychannel" --banner-position bottom

# баннер из .env (одна переменная BANNER: путь к файлу или текст)
python main.py subtitles

# без баннера, оставить исходные пропорции
python main.py subtitles -i clip.mp4 --no-fit-vertical

# цветокоррекция: насыщенность, резкость и лёгкая хроматическая аберрация
python main.py subtitles -i clip.mp4 --saturation 1.2 --sharpness 1.0 --chromatic-aberration 3

# ускорить ролик в 1.5 раза (видео и звук вместе)
python main.py subtitles -i clip.mp4 --speed 1.5
```

## Уникализация (обход детекции дубликатов)

Площадки (YouTube Shorts, TikTok, Reels) сравнивают ролики не только побайтово,
но и по «перцептивному» отпечатку кадра и по звуку: два внешне одинаковых файла
получают близкие подписи и могут пометиться как неуникальные. Небольшой цветокор
и ускорение уже сдвигают эту подпись, но при большом числе похожих нарезок (одно
и то же аниме/фильм, одни и те же склейки) этого мало. Группа `UNIQUE_*`
добавляет к тому же быстрому проходу FFmpeg набор почти незаметных правок,
которые сдвигают все три отпечатка — побайтовый, кадровый и звуковой:

- `UNIQUE_MIRROR` — зеркалит кадр по горизонтали (`hflip`). Сильнее всего меняет
  кадровый отпечаток, но переворачивает и текст/надписи, которые есть в самом
  видео, поэтому по умолчанию выключено. Булев флаг: `UNIQUE_RANDOMIZE` его не
  меняет.
- `UNIQUE_CROP` — убирает N пикселей с каждого края кадра и растягивает картинку
  обратно до исходного размера (лёгкий «наезд»). Геометрия — самый эффективный
  приём: сдвигается положение каждого пикселя. Значение 3-8 незаметно.
- `UNIQUE_NOISE` — зернистость: на каждый кадр добавляется свежий шум (0..100).
  Даже 3-5 заметно меняют статистику кадра, по которой строится перцептивный хеш.
- `UNIQUE_BRIGHTNESS` (яркость, -1..1), `UNIQUE_CONTRAST` и `UNIQUE_GAMMA`
  (множители к `1.0`), `UNIQUE_HUE` (поворот оттенка в градусах) — лёгкие правки
  тона и цвета; складываются в те же фильтры `eq`/`hue`, что и `SATURATION`.
- `UNIQUE_PITCH` — микро-сдвиг высоты звука в процентах (например `0.5`).
  Длительность ролика и синхронизация со видео не меняются — сдвигается только
  тембр, а вместе с ним и аудио-отпечаток. `UNIQUE_LOUDNESS` включает нормализацию
  громкости (приводит к `-14 LUFS` — стандарту площадок), `UNIQUE_GAIN` добавляет
  сдвиг громкости в дБ.
- `UNIQUE_METADATA` (включено) — в конце рендера метаданные контейнера стираются
  (устройство, GPS, дата, кодировщик) и вписывается свежий уникальный комментарий.
  Это меняет байтовый хеш файла без пере-кодирования картинки.
- `UNIQUE_RANDOMIZE` + `UNIQUE_JITTER` — разброс параметров: перед каждым рендером
  **числовые** значения уникализации слегка рандомизируются, поэтому выводы одного
  и того же монтажа получаются разными файлами (удобно при публикации одного клипа
  на много аккаунтов). Разбрасываются `UNIQUE_CROP` (±4px, 0..12), `UNIQUE_NOISE`
  (±3, 0..10), `UNIQUE_BRIGHTNESS` (±0.02, -0.1..0.1), `UNIQUE_CONTRAST` (±0.03,
  0.8..1.2), `UNIQUE_GAMMA` (±0.03, 0.8..1.2), `UNIQUE_HUE` (±3°, -8..8) и
  `UNIQUE_PITCH` (±0.5%, -2..2). Булевы флаги (`UNIQUE_MIRROR`, `UNIQUE_LOUDNESS`,
  `UNIQUE_METADATA`) и прочие эффекты (`SATURATION`, `SHARPNESS`,
  `CHROMATIC_ABERRATION`, `SPEED`) не меняются. `UNIQUE_JITTER` (`0..1`) —
  множитель амплитуды разброса (0.5 — половина, 1 — полный).

Все правки применяет тот же быстрый проход FFmpeg, что и цветокор, — до вшивания
субтитров и баннера, поэтому текст остаётся чётким, а рендер не замедляется. При
нейтральных значениях проход пропускается, как и раньше; команда `music` картинку
не трогает и уникализацию не применяет.

Примеры:

```bash
# базовый набор: микро-обрезка, зернистость и лёгкий тон
python main.py subtitles -i clip.mp4 --unique-crop 4 --unique-noise 3 --unique-contrast 1.03

# зеркало — сильнее всего меняет кадр (не годится, если в видео есть текст)
python main.py all --unique-mirror

# звук: микро-сдвиг высоты и нормализация громкости
python main.py subtitles -i clip.mp4 --unique-pitch 0.5 --unique-loudness

# случайный вариант на каждый рендер (для массовой публикации)
python main.py all --unique-randomize --unique-jitter 0.6
```

## Тестовый кадр (команда preview)

Настройку картинки удобно подбирать на **одном кадре**, а не на целом рендере.
Команда `preview` берёт **один случайный кадр** из исходного видео и прогоняет
его через те же этапы, что и настоящий рендер, после чего сохраняет результат
картинкой:

1. случайный кадр из случайного входного видео;
2. цветокоррекция и эффекты (тот же FFmpeg-фильтр, что и при рендере);
3. доводка до вертикального кадра 9:16 с размытым фоном (`FIT_*`,
   `BACKGROUND_*`);
4. субтитры и баннер.

Распознавание речи **не запускается**: если субтитры включены, вместо текста
рисуется заглушка `тестовый кадр` (тем же рендерером, что и настоящие реплики),
поэтому разные настройки субтитров и баннера проверяются за секунды — без ожидания
Whisper. Результат пишется в `OUTPUT_DIR/preview_frame.png`.

```bash
# один случайный кадр с текущими настройками из .env
python main.py preview

# сравнить настройки на одном и том же кадре (фиксированное время — 5 секунд)
python main.py preview --time 5

# быстрый тест эффектов и размытия фона без полного рендера
python main.py preview --saturation 1.2 --sharpness 1.0 --background-blur 40

# сразу несколько случайных кадров (в т.ч. из разных видео в папке)
python main.py preview -i video --count 4

# только картинка, без субтитров
python main.py preview --no-subtitles-enabled

# баннер в тестовом кадре
python main.py preview --banner "@mychannel" --banner-position bottom
```

- `--count N` — сколько случайных кадров отрисовать (по умолчанию 1). При
  нескольких файлах именуются `preview_frame_1.png`, `preview_frame_2.png`, ...;
- `--time SECONDS` — взять этот момент вместо случайного (удобно сравнивать
  настройки на неизменном кадре);
- `--[no-]subtitles-enabled` — рисовать ли пробную реплику субтитров;
- все флаги картинки (`--[no-]fit-vertical`, `--fit-aspect-ratio`,
  `--background-blur`, `--banner`, `--banner-position`, `--saturation`,
  `--sharpness`, `--chromatic-aberration`, `--speed`, а также флаги уникализации
  `--unique-*`) перекрывают `.env` на один запуск. Уникализация в тестовом кадре
  видна так же, как в готовом ролике (кроме `UNIQUE_PITCH`/`UNIQUE_LOUDNESS`/
  `UNIQUE_GAIN` и метаданных — они относятся к звуку и контейнеру).

## Скольжение по кадру (SLIDE_EFFECT)

Монтажный эффект на самом первом этапе — **при нарезке** клипа (до вертикальной
вставки, цветовых эффектов, субтитров и баннера). Когда источник широкий, а для
9:16 мы обрезаем его края, этот эффект «домонтирует» картинку: окно вертикальной
обрезки плавно едет по кадру — вправо, затем влево, и так поочерёдно на каждом
переходе (склейке/фейде) внутри клипа. Так как края кадра иначе уходят в обрез,
скольжение «показывает» скрытые части и добавляет движения.

- `SLIDE_EFFECT` — включить/выключить эффект (`false` по умолчанию; в CLI —
  `--slide` / `--no-slide`).
- `SLIDE_TRANSITION_GAP` — переходы, отстоящие друг от друга ближе этого числа
  секунд (по умолчанию `3.0`), объединяются в одну группу, и скольжение идёт
  сразу через всю группу, а не начинается заново на каждой склейке. За счёт
  группировки каждое скольжение длится минимум это число секунд: переходы
  ближе `gap` к началу или к концу клипа пропускаются (исключение — клип,
  который сам короче `gap`).
- `SLIDE_RANGE` — доля от полного горизонтального хода окна обрезки (по
  умолчанию `1.0`; в CLI — `--slide-range`). `1` — окно едет от самого края
  широкого кадра до противоположного (весь доступный ход); `0` — движения нет,
  окно стоит по центру; промежуточные значения (например `0.5`) оставляют
  одинаковый отступ от обоих краёв, до которых может уезжать кадр.

Переходы ищет `PySceneDetect` (склейки — `ContentDetector`, фейды —
`ThresholdDetector`). Если библиотека не установлена, включается встроенный
детектор на OpenCV (разница соседних кадров), поэтому эффект работает и без неё.
Вертикальное положение окна по-прежнему следует за лицом, а по горизонтали им
управляет скольжение. Если переходов не найдено — по клипу проезжает одна
плавная панорама. Когда ширина кадра не обрезается, эффект пропускается
автоматически.

Пример:

```bash
# нарезка со скольжением по кадру (порог группировки переходов — 3 с)
python main.py clip --slide --slide-transition-gap 3
# тот же эффект, но кадр едет лишь на половину хода (отступ от краёв)
python main.py clip --slide --slide-range 0.5
```

## Как это работает

1. **Скачивание** — `yt-dlp` (локальный файл берётся как есть).
2. **Распознавание** — `faster-whisper` (с таймингами по отдельным словам),
   результат кэшируется в `.srt` и сразу режется на короткие реплики-субтитры.
3. **Индексация визуала** *(опционально, `VISUAL_INDEXER_ENABLED=true`)* —
   `visual_indexer.py` анализирует кадры по сценам (PySceneDetect, иначе
   OpenCV) и описывает происходящее на экране: эмоции, действия, объекты,
   графику. Движок — локальный Florence-2 (`VISUAL_INDEXER_TYPE=florence`,
   `transformers` + `torch`) или облачный Gemini Flash — по кадрам
   (`VISUAL_INDEXER_TYPE=gemini`) либо целиком по видеофайлу
   (`VISUAL_INDEXER_TYPE=gemini_video`, Files API). Описания подмешиваются к
   транскрипту, поэтому ранжирование учитывает синергию слов и картинки.
   В лог ранжирования окно визуала попадает урезанным (`VISUAL_TEXT_MAX_CHARS`,
   300 символов на окно): многословные подписи Florence-2 иначе занимали почти
   весь промпт и топили саму речь, из-за чего модель выбирала моменты вслепую.
   Готовый индекс сохраняется в `OUTPUT_DIR` (`<video>.visual.json`) и
   переиспользуется на следующих запусках (`VISUAL_INDEXER_CACHE=true`), так
   что повторная нарезка того же ролика с другими настройками клипов не тратит
   лишние запросы к Gemini/Florence.
4. **Ранжирование** — LLM оценивает каждый момент 0–100 по «вирусной» рамке
   (хуки, эмоциональные пики, мнения-бомбы, откровения, конфликт, цитаты, пики
   историй, практическая польза) и заодно придумывает для каждого клипа
   **название** (`title`) и **краткое описание** (`description`) на 1–2
   предложения — они нужны для заполнения полей при публикации.
5. **Привязка к фразам, дедупликация и отбор** — границы кандидатов выравниваются
   по целым фразам транскрипта (`CLIP_SNAP_TO_TRANSCRIPT`), схлопнувшиеся в одно
   окно дубликаты отбрасываются, и остаётся топ `NUM_CLIPS`. Момент, размеченный
   LLM слишком коротко (на пару реплик бывает и 0,15 с), достраивается целыми
   репликами до `CLIP_MIN_DURATION` секунд (по умолчанию 15); если рядом с уже
   отобранными клипами места на целый клип нет, момент пропускается, а слот
   достаётся следующему кандидату по оценке — в нарезку не уходит огрызок в
   2–3 секунды.
6. **Нарезка и кроп** — `ffmpeg` режет, OpenCV трекает лицо для вертикального кадра.
7. **Постобработка** *(опционально)* — кадр доводится до 9:16 (пустые места
   закрывает размытая копия видео), применяются цветокоррекция и эффекты
   (`SATURATION` / `SHARPNESS` / `CHROMATIC_ABERRATION`), при `SPEED` ≠ 1
   меняется скорость видео и звука (субтитры пересчитываются под новый тайминг),
   накладывается баннер,
   вшиваются субтитры, под звук подмешивается музыка.

## Информация для площадок

В конце команд `clip` и `all` рядом с готовыми клипами пишется текстовый файл
`output/shorts_info.txt` — шпаргалка для заполнения полей при публикации. Для
каждого шортса в нём есть **название** и **описание**, которые LLM придумывает
вместе с выбором хайлайтов:

```
Информация о шортсах (для заполнения на площадках)
==================================================

Источник: talk.mkv

#1
Название:    Почему никто не говорит об этом
Описание:    Разбираем неочевидный момент, который меняет взгляд на тему. Коротко и по делу.
Теги:        #anime #shorts #аниме
Файл:        short_01_talk.mp4
```

Копируйте название и описание прямо отсюда — вводить их вручную не нужно.
Вместе с текстовой шпаргалкой рядом пишется машиночитаемый
`output/shorts_info.json` (те же поля: `title`, `description`, `tags`, `file`, ...).
Именно его читает команда `publish` (см. ниже), поэтому для публикации ничего
вводить руками не нужно. У каждого шортса теперь есть и **теги** (хэштеги) — их
LLM придумывает вместе с хайлайтом, а в JSON они лежат в ключе `tags`.
Те же поля доступны и в JSON-результате пайплайна (`--output-json`).

## Публикация (YouTube / TikTok)

Команда `publish` загружает готовые клипы на **YouTube** (через YouTube Studio)
и **TikTok** (через TikTok Studio) автоматизацией браузера. Всё работает через
**постоянные браузерные профили**: профиль — это именованный каталог Chromium, в
котором лежат куки/логины сразу для всех платформ. Логин делается один раз,
дальше загрузка идёт без участия человека.

Логика загрузки портирована из проекта
[`social-auto-upload`](https://github.com/dreammis/social-auto-upload).

Браузерная автоматизация работает на анти-детект движке
[ShardX](https://github.com/ProxyShard/ShardBrowser) через локальный HTTP API
приложения **ShardX Launcher**: спуфинг отпечатка на уровне движка
(WebGL/WebGPU/Client Hints/TLS/шрифты), свой Chromium и куки в профиле лаунчера;
установка Chrome не нужна.

### Установка браузерного стека

Публикация управляет установленным приложением **ShardX Launcher** через его
локальный HTTP API (`http://127.0.0.1:40325` по умолчанию). Нужно:

1. установить и запустить **ShardX Launcher**;
2. в *Settings → Automation API* включить API и скопировать **Bearer-токен**;
3. прописать токен в `.env` (см. `PUBLISH_SHARDX_API_TOKEN` ниже).

```bash
# python-сторона: HTTP-клиент к API лаунчера + stealth-подключение по CDP
pip install httpx patchright
```

Отдельно ставить Chrome/Chromium не нужно: ShardX Launcher запускает собственный
браузер и спуфит отпечаток внутри движка, а куки и отпечаток хранит сам профиль
лаунчера (id профиля запоминается в `meta.json` рядом с профилем).

### Профили и авторизация

```bash
# открыть браузер профиля (создаётся автоматически) и залогиниться в YouTube и TikTok
python main.py publish manual --profile profile_1

# только страница логина TikTok; несколько профилей сразу — через запятую
python main.py publish manual --profile profile_1 --platform tiktok
python main.py publish manual --profile profile_1,anime_ru

# проверить, живы ли куки; список профилей и история загрузок
python main.py publish check --profile profile_1
python main.py publish profiles
```

В ручном режиме скрипт открывает окно и просто ждёт: логинитесь, настраиваете что
нужно, закрываете окно — **все куки профиля сохраняются автоматически**.

Публикатор и лаунчер связаны по имени. Если профиль уже есть в **ShardX Launcher**
(создан там вручную или остался от старого SDK), он подхватывается автоматически,
как только вы назовёте его через `--profile <имя>` — отдельная регистрация не
нужна. `publish profiles` дополнительно показывает имена профилей, которые есть в
лаунчере, но ещё не «усвоены» публикатором. При этом `--profiles all` перебирает
только уже усвоенные профили, чтобы клипы не улетели в случайные профили лаунчера.

### Загрузка

```bash
# все клипы × все профили × обе платформы
python main.py publish upload

# только YouTube и только выбранные профили
python main.py publish upload --profiles profile_1,anime_ru --platforms youtube

# что будет загружено (браузер не открывается)
python main.py publish upload --dry-run

# один файл, unlisted, с паузой 60 c между загрузками
python main.py publish upload --video output/short_01_talk.mp4 --visibility unlisted --delay 60

# повторно залить всё / только то, что упало
python main.py publish upload --rerun
python main.py publish upload --rerun-failed
```

Клипы по умолчанию берутся из `PUBLISH_OUTPUT_DIR` (или `--output-dir`) вместе с
`shorts_info.json`; заголовок, описание и теги берутся оттуда. Уже опубликованное в
конкретный (профиль, платформа) повторно не заливается — учёт ведётся в SQLite
(`PUBLISH_DB`). Флаги выбора: `--profiles all|p1,p2`, `--platforms all|youtube|tiktok`,
`--only 1,short_03`, `--limit N`.

Шпаргалка (`shorts_info.json` / `shorts_info.txt`) пишется один раз, при нарезке
клипов, поэтому её записи могут «устареть»: если вы вручную удалили неудачный клип из
папки `output`, он всё ещё будет в шпаргалке. Перед загрузкой каждая запись
сверяется с файловой системой, и клипы, которых больше нет на диске, **пропускаются**
с предупреждением в логе — их не пытаются залить и не считают ошибкой загрузки.
Оставшиеся клипы публикуются со своими названиями/описаниями/тегами по порядку.

### Распределение клипов и расписание

Клипы **не дублируются между профилями**: они раздаются по кругу (`clip_i -> профиль_(i mod N)`).
Один и тот же клип попадает в один профиль, но публикуется там на выбранных площадках (YouTube и TikTok).

* `PUBLISH_MODE=distribute` — клипы раздаются по профилям по кругу, публикация **сразу**;
* `PUBLISH_MODE=schedule` — то же распределение, но каждый клип встаёт в **расписание**.

В режиме `schedule` длина списка `PUBLISH_SCHEDULE` задаёт, **сколько клипов публикует каждый профиль**
(значение *r* — время *r*-го клипа этого профиля). Пример: два профиля и
`PUBLISH_SCHEDULE=2026-04-01T10:00, 2026-04-01T18:00` -> каждый профиль выложит по 2 клипа в 10:00 и 18:00.
Если клипов меньше, чем `профили x слоты`, выкладывается сколько есть (с предупреждением в логе).
Время — в часовом поясе канала YouTube (TikTok — локальное сервера). Флаги на один запуск: `--mode`, `--schedule`.

### Настройки (`.env`)

```env
PUBLISH_MODE=distribute                # distribute | schedule (как клипы распределяются по профилям)
PUBLISH_SCHEDULE=                      # ISO-даты для schedule: 2026-04-01T10:00, 2026-04-01T18:00
PUBLISH_PROFILE_DIR=browser_profiles   # где живут профили (в профиле — куки)
PUBLISH_DB=publish_state.sqlite3       # история загрузок / защита от дублей
PUBLISH_OUTPUT_DIR=output              # откуда брать клипы и shorts_info.json
PUBLISH_HEADLESS=false                 # для загрузки окно лучше оставлять видимым
PUBLISH_PROXY=                         # например http://127.0.0.1:7890 (для YouTube/TikTok из РФ); привязывается к профилю при создании
PUBLISH_TAGS=anime,shorts              # хэштеги по умолчанию, если у клипа их нет
PUBLISH_VISIBILITY=public              # public | unlisted | private (YouTube)
PUBLISH_YT_PLAYLIST=                   # необязательный плейлист YouTube
PUBLISH_DELAY=30                       # пауза между загрузками, сек

# ShardX Launcher — локальный HTTP API (приложение должно быть запущено):
PUBLISH_SHARDX_API_URL=http://127.0.0.1:40325   # адрес API лаунчера
PUBLISH_SHARDX_API_TOKEN=              # Bearer-токен из Settings -> Automation API (обязателен)
PUBLISH_SHARDX_PLATFORM=Windows        # Windows | macOS | Linux (отпечаток для нового профиля; "" -> хост)
PUBLISH_SHARDX_NOISE=                  # canvas,webgl,audio,client_rects,sensors,fonts
PUBLISH_SHARDX_WEBRTC=auto             # auto | tcp_only | block
PUBLISH_SHARDX_LANGUAGE=en-US          # язык браузера: en-US | ru-RU | "" ("" -> лаунчер берёт из гео)
```

Каталог `browser_profiles/` содержит куки, поэтому он в `.gitignore`. Любой флаг
команды перекрывает значение из `.env` на один запуск.

from shorts_generator import load_settings, generate_shorts

settings = load_settings(extra={"input": "URL", "num_clips": 5})

## Устранение неполадок

- **Whisper не нашёл речи** — нет речи или не тот язык; задайте `WHISPER_LANGUAGE`.
- **Музыка не добавилась** — проверьте, что `MUSIC` указывает на существующий файл
  или папку.
- **Предупреждение про шрифт** — `FONT` не найден; задайте `FONT` (путь к
  файлу-шрифту, имя файла или папку со шрифтами) или положите `.ttf`/`.ttc` в
  `fonts/`.
- **`ffmpeg` не найден** — установите его или задайте `FFMPEG_PATH`.
- **`open() got an unexpected keyword argument 'metadata_errors'`** — PyAV 19 убрал
  параметры метаданных из `av.open` (вместе с `metadata_encoding`), а
  `faster-whisper` их передаёт при декодировании аудио, поэтому распознавание
  падает ещё до старта модели. Поставьте PyAV 18:
  `python -m pip install "av>=18,<19"` — эта версия идёт abi3-колесом, так что
  подходит и для свежих Python. В `requirements.txt` зависимость уже закреплена.
- **Предупреждение «could not open … directly; retrying on a cleaned copy»** — во
  входном видео есть метаданные глав, на которых спотыкается парсер MoviePy 2.x
  (он падает на файлах ровно с одной главой). Инструмент сам делает очищенную
  копию без глав и лишних потоков и продолжает работу — на результат это не
  влияет. Копия создаётся только при необходимости и удаляется автоматически.
- **Хочется лучших моментов** — настройте `VIRALITY_CRITERIA` /
  `HIGHLIGHT_SYSTEM_PROMPT` в `shorts_generator/highlights.py` или смените
  `LLM_PROVIDER`. Включите `VISUAL_INDEXER_ENABLED=true`, чтобы ранжирование
  учитывало ещё и картинку.
- **Клипы выходят слишком короткими (2–3 секунды)** — моменты короче
  `CLIP_MIN_DURATION` (по умолчанию 15 секунд) автоматически достраиваются
  целыми репликами до минимума; момент, которому рядом с уже отобранными клипами
  не нашлось места на целый клип, пропускается, а его слот достаётся следующему
  кандидату по оценке. Если после этого клипов меньше, чем `NUM_CLIPS`, значит
  модель разметила мало разнесённых друг от друга моментов. Проверьте:
  - `CLIP_MIN_DURATION` не выставлен в 0 (0 отключает выравнивание);
  - в транскрипте действительно есть речь рядом с выбранными моментами —
    ранжирование шло по логу, где больше половины текста занимали описания
    визуала, и речь в нём тонула (см. шаг 3 выше про `VISUAL_TEXT_MAX_CHARS`).
    Если визуал не нужен, выключите его: `VISUAL_INDEXER_ENABLED=false` — тогда
    в промпт уйдёт только транскрипт;
  - при необходимости опустите `CLIP_MIN_DURATION` ниже (например, до 10).
- **Индексация визуала не работает** — проверьте `VISUAL_INDEXER_ENABLED=true`.
  Для `florence` нужны `torch`, `transformers`, а также `einops` и `timm` (их
  импортирует remote-код Florence-2); модель скачивается при первом запуске.
  Florence-2 работает только на `transformers` 4.x: на 5.x (и на самых поздних
  4.x, где появился `_supports_sdpa`) её remote-код падает с `AttributeError`.
  Проверенная связка:
  ```
  python -m pip install "transformers>=4.41,<4.54" einops timm
  ```
  Для GPU нужна CUDA-сборка torch — обычный `pip install torch` в Windows ставит
  CPU-версию, и тогда индексатор молча уходит на CPU (в логе `CUDA requested but
  unavailable; using CPU`):
  ```
  python -m pip install torch --index-url https://download.pytorch.org/whl/cu130
  ```
  Для `gemini` и `gemini_video` нужен `GEMINI_API_KEY`.
  Ставьте зависимости **в тот же интерпретатор**, которым запускается скрипт:
  если активен venv — активируйте его перед `pip install`; точный путь печатается
  в сообщении об ошибке (строка `Interpreter:`), готовую команду можно скопировать
  оттуда. Обычная причина «я же установил, а не работает» — пакеты ушли в другой
  Python.
- **Индексация визуала запущена, но не сработала** — запуск останавливается: если
  не хватает зависимостей или ключа (`florence` без `transformers`/`torch`/
  `einops`/`timm`, `gemini*` без `GEMINI_API_KEY`) — сразу, ещё до анализа сцен, с
  подсказкой, что установить; при любом другом сбое (таймаут API, нехватка VRAM,
  битая модель) — с
  причиной. Включённая опция либо даёт результат, либо честно останавливает запуск,
  а не игнорируется молча. Чтобы нарезать клипы без визуального контекста, выключите
  её: `VISUAL_INDEXER_ENABLED=false`.
- **Ошибка настройки `VISUAL_INDEXER_TYPE`** — допустимы `florence`, `gemini`,
  `gemini_video` или `none`.
- **Индекс визуала берётся из старого кэша** — результат сохраняется в
  `OUTPUT_DIR` (`<video>.visual.json`, рядом с `.srt`-кэшем транскрипта). Чтобы
  пересчитать его заново, удалите этот файл или запустите с
  `VISUAL_INDEXER_CACHE=false`. Кэш сам сбрасывается при изменении движка,
  модели или порогов сцен, а также если видеофайл обновился.
- **`could not reach the ShardX launcher …`** — приложение ShardX Launcher не
  запущено или API выключен. Запустите лаунчер и включите *Settings →
  Automation API*.
- **`the ShardX launcher rejected the API token (HTTP 401)`** — задайте
  `PUBLISH_SHARDX_API_TOKEN` равным токену из *Settings → Automation API*
  лаунчера.
